# 로컬 결정 모델 재측정 분석 — 2026-09-30

M3 Max(36GB)에서 결정 모델 9개(AnyJev raw·L0 포함)를 셋 7개로 다시 쟀다. 달라진 점은 네 가지다.

- **하네스**: 호출 하나하나를 원자료로 남긴다(`bench/runs/<셋>/<엔진>.jsonl`). report는 그 원자료로만 만든다(`bench/score.py`).
- **통계**: "어느 엔진이 나은가"는 Wilson 구간 겹침 대신 대응 McNemar 정확 검정으로 판정한다.
- **새 셋 4개**: Kev transfer-v4 dev, typed-decisions test, NSMC, KLUE-YNAT.
- **새 엔진 4개**: Winnow-E4B, Jeff-Qwen3.5-2B, Kev-0.8B, Kev-9B.

표와 수치의 정본은 `bench/runs/*/report.md`다. 이 문서는 해석만 한다.

## 결론

1. **정확도가 필요하면 Kev-9B·Kev-4B·Winnow-E4B 중에서 고른다. 셋의 차이는 생각보다 작다.**
   - 셋을 McNemar로 구분할 수 있는 곳은 typed-decisions(Winnow·Kev-9B > Kev-4B)와 transfer-v4의 Kev 정책 구조 홀드아웃뿐이다. Kev의 학습 분포인 BANKING77은 제외했다.
   - 30문항 셋, NSMC, KLUE-YNAT, transfer-v4 공개 출처에서는 구분되지 않는다.
2. **transfer-v4에서 Kev가 앞선 것은 Kev가 만든 정책 구조 홀드아웃 덕분이다.** 아래 "transfer-v4 분해" 절에 근거가 있다.
3. **속도가 필요하면 Kev-0.8B가 Ollaya보다 낫다.**
   - 지연은 비슷하다(짧은 state에서 28~58ms 대 15~55ms).
   - 정확도는 모든 셋에서 같거나 높다. typed-decisions, NSMC, KLUE-YNAT에서는 p < 0.001로 높다.
   - order-flip이 적다. 선택지 많은 셋에서 Kev-0.8B는 8~19%, Ollaya는 30~45%다.
4. **Kev-4B는 모델 카드의 transfer-v4 수치를 재현했다.**
   - clean 656문항에서 534/656(0.814, Wilson 0.782~0.842)이다. 카드는 0.817이라 536/656에 해당하고, 차이는 2문항이다.
   - 이 재현으로 하네스의 dict state 렌더(Kev `render` 이식)와 argmax 채점 규칙을 확인했다.
5. **typed-decisions에서 Winnow(0.7265)와 Kev-9B(0.720)는 카드가 Jev 1.13.0에 매긴 0.727 근처다.**
   - 카드 수치는 카드 쪽 하네스 값이다(미검증, 재실행하지 않음).
   - gold 분포와의 거리는 Kev-9B가 가장 가깝다(KL 0.209, Brier 0.107).
6. **학습 없는 AnyJev(Qwen3-8B)는 생각보다 강하다. 다만 느리고 확률이 과신이다.**
   - transfer-v4 공개 출처 588판단에서 raw·L0 모두 458개를 맞힌다. Kev-4B 454, Kev-9B 461, Winnow 460과 같다(Kev-4B 대비 p = 0.76).
   - KLUE-YNAT에서 75~76%로 상위 그룹과 같다(p ≥ 0.33).
   - typed-decisions에서는 61~63%로 뒤지고, gold와의 KL이 2.8~3.8이다(상위 그룹 0.2~0.3). 틀릴 때도 확신한다는 뜻으로 보인다(추정).
   - BANKING77에서 자기 README를 다시 재현했다(2026-09-29와 같은 수). 대응 검정으로는 L0의 정확도 향상도 실제로 있다(25 대 8, p = 0.005). 예전 README의 "300문항에선 안 보인다"는 Wilson 구간 겹침만 보고 내린 판정이었다.

## 측정 조건

- **실행 방식**: `scripts/measure.sh`가 엔진을 하나씩 띄우고, 재고, 내렸다. 순서는 가벼운 엔진부터다(Ollaya → Winnow → Kev-0.8B → Kev-4B → Kev-9B → Jeff → CLM). AnyJev raw·L0는 고아 서버를 내린 뒤 18:59~22:02에 따로 쟀다.
- **반복**: 30문항 셋은 3회, 나머지는 1회와 역순 호출 1회다.
- **Ollaya 모델**: 영어 셋에는 `laya`, 한국어 셋(한국어 30문항·NSMC·KLUE-YNAT)에는 `laya:multilingual`을 썼다.
- **CLM**: 30문항 셋과 BANKING77만 쟀다. 플랜 결정대로다. 원인은 상류 가중치 불일치(#15)로 좁혀졌고, 20~41%라 판단에 쓰지 않는다.
- **원자료 크기**: 원시 로그(.jsonl)는 모두 21.5MB이고, 셋당 최대 8.7MB(typed-decisions)다. 10MB를 넘지 않아 gzip하지 않았다.
- **원자료 내용**: 문항 id와 엔진 답(확률 포함)만 담는다. 원문(state)은 들어 있지 않다. 100문항씩 대조해 확인했다.
  - 라이선스가 걸린 원문은 `bench/data/`(gitignore)에만 있다.
  - typed-decisions와 KLUE-YNAT 로그에는 선택지 라벨 텍스트가 확률 키로 들어 있다.

## 셋별 해석

### transfer-v4 분해

transfer-v4 dev 764판단은 두 부분으로 나뉜다.

- 공개 출처 6개(`emotion`, `mmlu`, `paws`, `qnli`, `sciq`, `tweet_offensive`), 588판단
- Kev 쪽이 만든 정책 구조 홀드아웃 2개(`composition_holdout`, `legacy_holdout`), 176판단

모델 카드는 이 셋을 "six never-trained sources + held-out policy structures"라고 설명한다.

| 부분 | 판단 | Kev-4B | Kev-9B | Winnow | AnyJev raw | AnyJev L0 | Jeff | Kev-0.8B | Ollaya |
|---|---|---|---|---|---|---|---|---|---|
| 공개 출처 6개 | 588 | 454 | 461 | 460 | 458 | 458 | 428 | 388 | 396 |
| 정책 구조 홀드아웃 2개 | 176 | 160 | 157 | 125 | 113 | 114 | 99 | 111 | 87 |

McNemar 정확 검정:

| 비교 | 공개 출처 (b, c, p) | 홀드아웃 (b, c, p) |
|---|---|---|
| Kev-4B vs Winnow | 38, 44, 0.58 | 39, 4, < 0.001 |
| Kev-9B vs Winnow | 37, 36, 1.0 | 40, 8, < 0.001 |
| Kev-4B vs Kev-9B | 29, 36, 0.46 | 11, 8, 0.65 |
| AnyJev raw vs Kev-4B | 52, 48, 0.76 | 2, 49, < 0.001 |
| AnyJev raw vs Winnow | 43, 45, 0.92 | 13, 25, 0.07 |

- Kev가 transfer-v4 전체에서 Winnow를 앞선 것(p = 0.003·0.012)은 홀드아웃 176판단에서 온다.
- 공개 출처에서는 Kev-4B·Kev-9B·Winnow가 같고, 학습 없는 AnyJev도 같다.
- 홀드아웃은 Kev가 학습하는 프로그램 생성 정책 데이터에서 구조만 뺀 것이다. 그래서 "분포 밖"이라도 Kev에게 유리한 셋이다.
- 출처별 수는 report의 `## By source` 표를 더하면 나온다. 부분별 McNemar는 report에 없으므로 아래로 다시 계산한다.

```python
import sys; sys.path.insert(0, "bench"); import score
from pathlib import Path
_, items, runs = score.load_dir(Path("bench/runs/transfer-v4"))
src = {it["id"]: it["meta"]["source"] for it in items}
right = {e: {k: score.is_right(*v) for k, v in score.graded(items, recs).items()} for e, (_, recs) in runs.items()}
hold = lambda k: src[k[0]] in ("composition_holdout", "legacy_holdout")
b = sum(right["kev-4b"][k] and not right["winnow"][k] for k in right["winnow"] if not hold(k))
c = sum(right["winnow"][k] and not right["kev-4b"][k] for k in right["winnow"] if not hold(k))
print(b, c, score.mcnemar_exact(b, c))   # 38 44 0.58...
```

- **emotion 출처**는 모든 엔진이 어려워한다(51~67%). 여기서는 AnyJev(raw·L0 67%)가 가장 높고, 그다음이 Ollaya(62%)다.
- **paws**에서는 Jeff가 가장 높다(68/80, 85%). Jeff는 PAWS train split으로 학습했다(`jeff/src/jeff/data.py`). 이 80판단은 Jeff에게 학습 분포 안이다.
- **sciq**는 거의 모든 엔진이 90%를 넘는다(AnyJev L0 99%). 예외는 Ollaya(82%)와 Kev-0.8B(88%)다.

### typed-decisions

- **정확도**: Winnow 73%, Kev-9B 72%, Kev-4B 67%, AnyJev L0 63%, AnyJev raw 61%, Jeff 52%, Kev-0.8B 46%, Ollaya 36%(실패 35판단 제외)다.
- **McNemar**: Winnow와 Kev-9B는 구분되지 않는다(p = 0.529). AnyJev L0는 raw보다 낫다(82 대 42, p < 0.001). 나머지 쌍은 모두 p < 0.001이다.
- **gold 분포와의 거리**:
  - Kev-9B KL 0.209, Brier 0.107
  - Kev-4B KL 0.223, Brier 0.125
  - Winnow KL 0.286, Brier 0.128
  - AnyJev L0 KL 2.813, Brier 0.420 / raw KL 3.783, Brier 0.479. uniform(0.444)보다도 멀다. 확률을 0이나 1 가까이로 몰아서 틀릴 때 벌점이 커진 것으로 보인다(추정).
  - Winnow는 정확도가 같아도 분포는 Kev-9B보다 gold에서 멀다. 카드 리더보드가 정확도만 보면 이 차이가 가려진다.
- **기준 행**:
  - uniform 행(KL 0.444, Brier 0.238)은 카드 값과 같다.
  - 카드의 Prior(0.470)와 Uniform 정확도(0.308)는 재현하지 못했다. 카드 생성 코드가 공개되지 않았다(플랜 Decisions 참조).
  - report의 `(prior)` 행은 train soft gold의 워크플로·질문별 평균을 쓴 우리 정의다(957/2000, 48%).
  - Kev-0.8B(46%)와 Jeff(52%)는 이 prior와 비슷하거나 약간 높은 수준이다.
- **워크플로별**:
  - `invoice_processing`에서 Kev-9B(80%)와 Kev-4B(69%)의 차이가 가장 크다.
  - `agent_trace_observability`는 Jeff를 뺀 모든 엔진에서 가장 낮은 워크플로다(31~63%). Jeff는 `invoice_processing`이 가장 낮다(41%).
- **Jeff**: 카드 리더보드의 Jeff는 Jeff-Gemma4-E2B(0.561)다. 여기서 잰 것은 MLX 백엔드가 지원하는 Jeff-Qwen3.5-2B라 직접 비교하지 않는다.

### 한국어 (NSMC, KLUE-YNAT, 한국어 30문항)

### BANKING77 20-way

- **학습 분포 안**: Kev 세 크기는 모두 BANKING77 train으로 학습했다. 모델 카드 `datasets`와 `kev/data.py`의 `TRAINABLE`이 근거다.
  - 88~89%는 학습 분포 안의 수치이고, 여기서는 Kev-0.8B도 큰 크기와 구분되지 않는다(p ≥ 0.80).
  - 다른 셋에서는 0.8B가 확연히 뒤지므로, 이 셋은 Kev 크기 비교에도 쓰지 않는다.
- **학습하지 않은 엔진**: Winnow 81%, AnyJev L0 80%, AnyJev raw 75%, Jeff 65%, Ollaya 60%, CLM 20%다.
  - AnyJev는 자기 README를 재현했다. order-flip 68 → 22, 정확도 224 → 241로, 2026-09-29와 같은 수다. L0는 raw보다 낫고(25 대 8, p = 0.005), Winnow와는 같다(p = 0.868).
  - Jeff의 출처 목록에는 BANKING77이 없다. 대신 MASSIVE·CLINC150 인텐트를 학습했다(`docs/data-sources.md`).
  - Jeff는 order-flip이 24%로 높다.

### 영어 30문항

- **상위**: Kev-9B 90%, Kev-4B·Winnow 89%이고 서로 구분되지 않는다. AnyJev raw 82%, L0 81%는 Kev-9B보다 낮다(p = 0.049, 0.021). L0는 Winnow보다도 낮다(2 대 10, p = 0.039).
- **Jeff**: 64%로 가장 낮고(CLM 제외), ECE도 0.237로 CLM 다음으로 나쁘다.
  - 이 셋의 score 질문(긴급도·감정 등)이 Jeff에게 불리할 수 있다(미검증).
