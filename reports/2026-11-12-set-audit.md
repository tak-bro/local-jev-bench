# 세트 감사 (2026-11-12)

9개 세트의 항목과 2026-10-14 이후 커밋된 엔진 로그 전부(세트당 32~33개)를 항목 단위로 다시 읽었다. 확인한 것은 중복 입력,
정답 분포와 다수 클래스 기준선, 언어 혼입, 그리고 상위 엔진이 모두 틀린 판단이다. 새로 측정한 엔진은 없다.

## 요약

- **clinc-oos v1은 버그다.** 순위가 대부분 `oos` 옵션을 고르는 성향에서 나왔다. 빌더를 고쳐 v2를 만들었고, v1 결과는
  README에서 철회 표시했다. v2로 재측정해야 비교할 수 있다.
- **한국어 세트의 라벨 노이즈는 약 4%다.** NSMC 11/300, KLUE-YNAT 12/300. 후보를 빼면 모든 엔진이 약 3점씩 함께
  올라 순위는 그대로다. 300문항에서 1~2점 차이는 이 노이즈와 표본 오차 안이다.
- **영어·한국어 비교 수단이 30문항(105판단)뿐이었다.** MASSIVE en-US/ko-KR 병렬 세트(`massive-en`·`massive-ko`, 300쌍)와
  짝지은 비교 도구 `bench/lang_gap.py`를 추가했다.
- 나머지(transfer-v4, typed-decisions, BANKING77-20, 30문항 두 개)에서는 빌드 결함을 찾지 못했다. transfer-v4에서 상태가
  같은 132개는 업스트림이 의도한 옵션 순서·`none_of_these` 변형이다. EN/KO 30문항은 id와 정답이 30/30 같다.

## clinc-oos v1

`clinc_oos()`는 "train에서 가장 흔한 20개 인텐트"를 골랐다. CLINC150 `plus`에서는 실제 인텐트가 모두 train 100개씩이고
`oos`만 250개라서, `oos`가 설명 없는 이름 그대로 옵션에 들어갔다. 그 결과는 다음과 같다.

- 선택 300개 중 186개(62%)의 정답이 `oos`였다. 실제 인텐트 문항은 114개뿐이다.
- yes/no 100개는 정답이 전부 False였다. 항상 "아니오"라고 답하면 100%다. 게다가 질문("Is this request about one of
  these intents: …, oos, …?")이 `oos`를 인텐트로 나열해서, "예"가 논리적으로 맞는 답이 된다.
- 같은 OOS 발화 18개가 선택 문항과 yes/no 문항에 모두 들어갔다(같은 1000개 풀에서 따로 뽑았다).

인텐트 114/114인데도 73.5%다. Kev-9B의 OOS yes/no 14/100은 위의 모순된 질문을 글자 그대로 읽은 결과일 수 있다.

v2(`make_sets.py clinc-oos`, 500항목)의 구성:

- 실제 인텐트 150개 중 seed 0으로 20개를 뽑는다. `oos`는 절대 옵션이 아니다.
- 선택 300개, 범위 안 yes/no 100개(정답 True), 범위 밖 yes/no 100개(정답 False). 한쪽으로만 답하면 yes/no의 절반을 맞힌다.
- 발화는 한 번만 쓴다. OOS 발화는 같은 `plus` test에서 가져오므로 GitHub `data_full.json` 의존이 없어졌다.
- `meta.source`는 `clinc150`(선택)·`clinc-in`·`clinc-oos`이고, `report.md`의 "By source"가 세 부분을 따로 보여준다.

## 한국어 라벨 노이즈

`bench/consensus.py`는 정확도 상위 8개 엔진(panel)이 모두 같은 오답을 낸 판단을 라벨 노이즈 후보로 뽑는다. 전체 표와
후보 목록은 `reports/2026-11-12-consensus.md`에 있다.

- **NSMC:** 11/300(3.7%). 반어("빨리 다 죽여주세요"), 칭찬 문장에 낮은 별점("…재밌었다." 정답 부정) 등 별점 기반 라벨의
  한계가 대부분이다.
- **KLUE-YNAT:** 12/300(4.0%). "페드로 마르티네스 홈런…"(정답 `세계`), "제18회 박인환문학상에 김학중 시인"(정답 `사회`)처럼
  정답 쪽이 틀렸거나 연합뉴스 섹션 기준이라 제목만으로는 맞힐 수 없는 항목이다.
- 후보를 빼도 KLUE-YNAT 최고는 pplx-decider 86%(249/288)다. 남은 오차는 노이즈보다는 우리가 쓴 분야 설명
  (`YNAT_TOPICS`)과 KLUE 라벨 기준의 차이 쪽이 크다. 설명은 바꾸지 않았다. 정답에 맞춰 설명을 고치면 세트를 엔진 결과에
  맞추는 셈이다.

## 영어 대 한국어

`bench/lang_gap.py`로 기존 30문항 쌍(`questions` 대 `questions_ko`, 105판단)을 짝지어 비교했다.

- 33개 엔진 중 5개만 한국어에서 유의하게 떨어진다(p < 0.001). d1-omni −40점, ollaya-td −35, coba-1b −31, von −25,
  coba-400m −24.
- 나머지 28개는 −10.5점에서 +11.4점 사이다. p < 0.05인 것은 jeff 하나(+11.4, p = 0.043)뿐이다. 105판단으로는 수 점의
  격차를 가릴 수 없다.

MASSIVE 병렬 세트(`massive-en`·`massive-ko`)의 구성:

- en-US test에서 가장 흔한 20개 인텐트(`general_quirky` 제외)를 쓴다. en-US와 ko-KR에서 같은 id·같은 인텐트이고,
  MASSIVE 검수자 누구도 ko-KR 번역에서 인텐트가 깨졌다고 표시하지 않은(intent_score 0이 없는) 300쌍이다.
- 두 세트는 id·옵션·영어 질문·정답이 같고 발화만 다르다. 측정하면 언어 차이가 300판단 단위로 짝지어진다.
- ko-KR은 직역이 아니라 현지화본이다(예: "recipe for risotto" → "볶음밥 레시피"). 격차에는 번역 품질과 현지화가 함께 섞인다.
