# 전체 재측정 분석 — 2026-10-16

M3 Max(36GB)에서 2026-10-14~16에 엔진 19종 × 셋 8종을 유휴 머신에서 한 번에 다시 쟀다. 표와 수치의 정본은
`bench/runs/*/report.md`다. 이 문서는 해석만 한다.

## 결론

1. **정확도는 전부 재현됐다.** 이전 측정(09-30~10-12)이 있던 엔진×셋 129칸이 정답 수까지 같다. 예외는
   AnyJev L0 두 칸이다. transfer-v4가 572 → 571, typed-decisions가 1253 → 1252로 각 1판단씩 줄었다.
   L0 배치 prior가 호출 이력에 따라 쌓이는 구조라 그 정도 흔들림은 예상 범위다. 이전 README의 McNemar 결론은
   이 데이터로도 성립한다.
2. **지연 시간은 크게 바뀌지 않았다.** 엔진별 첫 호출 p50 중앙값은 이전 값의 0.85~1.08배다. 09-30 행 옆에서
   돌던 vLLM 서버(`--gpu-memory-utilization 0.7`, 유휴)의 영향은 작았다. Kev-4B·Kev-9B는 오히려 1.04배·1.08배로
   조금 느리다. 예외는 Ollaya-td(0.68배)다. 이제 모든 행이 같은 조건이라 엔진 간 지연 비교가 성립한다.
3. **JevK5는 이제 잴 수 있다.** 10-10에 났던 `llama_decode failed (-3)`가 재현되지 않았다(Ollaya가 Metal
   Q8_0으로 로드). 30문항 셋에서는 상위 그룹이다. 영어 90%, 한국어 88%로 Kev·Winnow·Clef·Decider-4B와 같다
   (p ≥ 0.146). KLUE-YNAT는 74%로 Kev·Winnow-E4B와 같다. 큰 영어 셋에서는 상위 그룹 아래다. transfer-v4는
   76%로 Winnow-E4B와 같고(p = 0.920) Kev보다 낮다(p ≤ 0.004). typed-decisions는 65%로 Kev-4B와 같고
   (p = 0.056) Kev-9B·Winnow·Clef보다 낮다. 선택지 20개 셋(BANKING77-20·clinc-oos)은 cold 호출에서
   `TOO_MANY_OPTIONS`로 거절한다. 측정 실패가 아니라 엔진의 옵션 예산 제약이다.
4. **clinc-oos는 Clef가 단독 1위다.** 95%(380/400)로 다른 모든 엔진을 앞선다(p < 0.001). 선택 300개
   중 283개, 범위 밖 100개 중 97개로 두 절반 모두 강하다. 그다음은 Kev-4B와 Winnow-12B로 84%다(둘 사이
   p = 0.894). 두 하위 셋은 성격이 갈린다.
   - Kev-9B는 의도 선택은 Clef 다음(269/300)이지만, 범위 밖 요청 100개 중 86개를 범위 안이라고 답한다.
     그래서 71%로 Kev-4B보다 낮다(p < 0.001).
   - Clef-flash는 반대다. 범위 밖은 97/100인데 선택은 197/300이다.
   - Ollaya(79%)와 Ollaya-td(77%)는 점수 대부분을 범위 밖 절반(96~99/100)에서 얻는다.
5. **Kev-9B의 10-10 변화는 typed-decisions만이 아니었다.** 이전 README는 "typed-decisions 외 재현"이라고
   썼지만, 09-30 → 10-10에 7셋 전부가 움직였다. 영어 30은 95 → 93, 한국어 30은 94 → 91,
   BANKING77-20은 267 → 271, transfer-v4는 618 → 620, NSMC는 257 → 261, KLUE-YNAT는 220 → 218,
   typed-decisions는 1440 → 1378이다. 이번 재측정은 10-10 값을 그대로 재현했다. 09-30 로그가 git
   `9f5ba1c`에 남아 있어 짝 검정이 가능하다(아직 안 함). README의 표와 해당 문단을 이번에 바로잡았다.

## 측정 조건

- 프로토콜: 30문항 두 셋은 `--reps 3`, 큰 셋 6개는 `--reps 1`, 모든 엔진 `--timeout 300`. CLM은 기존 범위
  (30문항 셋과 BANKING77)를 유지했다.
- 장치(Ollaya 서버 로그 `loaded model ... device=`): Decider-4B·Decider-2B·Decision-Eos·Ollaya-td는 CPU F32
  (ONNX), Laya는 Metal(MLX), Winnow-E4B·Winnow-12B·JevK5는 Metal Q8_0(llama.cpp)이다.
- 메모리 압력: Jeff 2B·0.8B가 typed-decisions·NSMC·KLUE-YNAT·clinc-oos에서 `warn`까지 갔고, 나머지는 전부
  `normal`이었다(Clef 포함).
- 소요: 큰 셋 단계에서 가장 오래 걸린 건 Decider-4B(49593초, 약 13.8시간), Decider-2B(17099초),
  Clef(16479초), AnyJev L0(10572초)다.

## 사고 기록

- 첫 러너가 큰 셋에 `--reps 1`을 빠뜨려, 13개 엔진의 큰 셋이 `bench/run.py` 기본값인 reps 3으로 돌았다.
  `score.py`는 한 디렉터리에 reps가 섞이면 거부하므로 모든 큰 셋 단계가 rc=1로 끝났다. 약 10시간을 버리고
  reps 1로 다시 쟀다. 배치 재측정 때는 첫 단계 로그 헤더의 `"reps"`를 바로 확인할 것.
