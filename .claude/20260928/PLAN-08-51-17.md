## Spec

**Objective** — Jev(TypeSafe)와 같은 타입 결정 API(`/v1/systemone`)를 이 Mac(M3 Max · 36 GB · macOS 26.6.2)에서 API 키 없이 로컬로 띄운다.
엔진은 vllm-metal부터 올리고, 그 위에 CLM-8B를 붙인 뒤 Ollaya(Laya)와 같은 질문셋으로 비교한다. 지금은 vLLM도 Ollaya도 설치돼 있지 않고, 로컬에서 결정 모델을 돌릴 방법이 없다.

**Success Criteria**
- [ ] `vllm --version` 이 vllm-metal 빌드로 응답한다
- [ ] 소형 임베딩 모델 pooling 서버가 `127.0.0.1:8091/v1/embeddings` 에 벡터를 돌려준다 (차원 > 0, L2 노름 0.99~1.01)
- [ ] Qwen3-8B pooling 서버가 `127.0.0.1:8090/v1/embeddings` 에 4096차원 벡터를 돌려준다 (L2 노름 0.99~1.01)
- [ ] `clm-serve` 가 `:8700` 에 떠 있고, CLM README 예제 요청이 `department=billing`, 그 확률 ≥ 0.85를 돌려준다
- [ ] 같은 README 예제에서 `urgency.noul` 이 0.41±0.10, `frustration.score` 가 1.98±0.20 안에 든다 (레퍼런스는 RTX 4090 수치)
- [ ] Ollaya `laya` 가 같은 README 예제에 `/v1/systemone` 형식으로 답한다
- [ ] `bench/report.md` 에 두 엔진의 cold 1회·warm p50·p95 지연(ms)과 질문셋 정답률 표가 생성된다
- [ ] 벤치 중 두 서버를 동시에 띄운 상태에서 커널 메모리 압력이 critical로 가지 않는다 (`kern.memorystatus_vm_pressure_level`, 요청마다 샘플)

## Boundaries

Do:
- 모든 서버 기동을 `scripts/` 셸 스크립트로 남겨 재현 가능하게 한다 (포트·모델·max-model-len·host 고정)
- 모든 서버는 `127.0.0.1` 에만 바인드한다 — vLLM 기본 host는 전체 인터페이스라 `--host 127.0.0.1` 을 명시한다
- 서버 스크립트는 기동 전에 포트 점유를 확인하고(`lsof -iTCP:<port> -sTCP:LISTEN`), 점유 중이면 exit 1로 멈춘다
- smoke·bench는 exit code로 통과와 실패를 가린다
- Qwen3-8B는 원본(bf16) 체크포인트부터 쓴다 — CLM 헤드가 학습한 임베딩과 맞추기 위해서다

[Warning] Ask First:
- vllm-metal이 원본 `Qwen/Qwen3-8B` 로드를 거부할 때 MLX 양자화 체크포인트로 바꾸는 것 (임베딩 드리프트 위험)
- 전역 설치(brew·Ollaya 설치 스크립트 외 `pip install --user` 등)나 GitHub 원격 레포 생성

🚫 Don't:
- `serve_qwen3_8b.sh` 를 그대로 쓰지 않는다 (`CUDA_VISIBLE_DEVICES` 전제)
- 수치를 README 레퍼런스와 맞추려고 헤드나 임베딩을 손대지 않는다 — 차이는 리포트에 기록만 한다
- `~/.config` 나 셸 rc 파일을 수정하지 않는다
- 엔진별 클라이언트를 따로 만들지 않는다 — 둘 다 `/v1/systemone` 이라 base URL만 다른 클라이언트 하나를 쓴다
